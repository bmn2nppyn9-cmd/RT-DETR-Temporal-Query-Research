# 简历与面试项目讲解

## 项目定位

**NVIDIA GPU 上的 RT-DETR 推理性能优化与验证工具链。** 先定位模型开销，调整实际执行路径，再用 CUDA 计时与精度评测验证收益；配套实现可追溯、可测试的运行工具。

## 简历表述

- 在 RTX 5070 Ti Laptop 上开展 RT-DETR 模块 profiling 与深度/query/分辨率扫描，建立 30 点静态精度—延迟网格和 27 点三维计时网格。
- 通过推理期 decoder 深度裁减，在同权重、FP32、fused、batch=1、640 输入条件下，将纯网络前向 P50 从 18.24 ms 降至 13.70 ms，降低约 24.9%，AP50 代价为 1.88pp；报告 P95/P99 以检验尾延迟预算。
- 实现预热、CUDA 同步与多轮交错测量，并构建性能预算面板，明确区分子集/全量精度、纯前向/端到端时间和历史/新增证据。
- 实现隔离 worker、工作区互斥、超时进程树清理、失败状态和 SHA256 产物追溯；12 项测试及 Windows/Linux CI 通过。
- 实现时序 query 缓存与晚层注入，用两帧训练探索轻量模型精度补偿；11 项模型回归及最小训练—推理—评测闭环通过。

## 面试叙事

1. 工程目标：为单帧推理预算寻找执行成本更低的 RT-DETR 配置，同时量化精度代价。
2. 性能定位：分别测 backbone/encoder/decoder，避免只看 FLOPs 或一次 wall time。
3. 优化动作：真实跳过深层 decoder，扫描 query 数和分辨率，比较成本与精度。
4. 验证结果：6→3 层 P50 下降 24.9%；15ms 预算下 P95 达标、P99 略超，不能只报平均值。
5. 工程复现：固定依赖、统一受管配置、保存日志和产物哈希，测试失败、并发、超时及指标边界。
6. 精度补偿：时序传播是独立训练扩展；尚不能把其精度与静态加速拼成无损加速结果。
