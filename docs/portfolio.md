# 面试与简历项目讲解

## 项目定位

**面向有状态视觉模型的本地 ML 实验与性能验证平台。** 用 RT-DETR 时序查询传播作为真实工作负载，将模型性能研究变成配置驱动、可追溯、可测试的实验流程。

## 可以写进简历的内容

- 设计并实现标准库控制层与独立模型 worker，统一数据准备、两帧训练、连续帧推理、评测和回归任务。
- 实现独占工作区、输入/输出前置检查、失败与超时进程树清理、原子 manifest 及 SHA256 产物追溯，并通过故障注入测试验证。
- 构建离线性能预算面板，管理 30 点静态消融、27 点三维计时和 5 组短训证据，显式区分精度子集、计时范围和端到端指标。
- 改造 RT-DETR 时序查询缓存、晚层注入与两帧训练路径；历史同协议实验 AP50 从 38.77% 到 40.45%，完整限制见 benchmarking.md。

不要添加未经测量的 QPS、线上 SLA、生产规模、集群调度、GPU kernel 优化或 RK3588 性能。

## 三分钟讲解

1. 问题：研究脚本依赖本机路径、输出互相覆盖、训练失败仍退出成功，性能数字缺少统一来源。
2. 设计：CPU 控制层检查配置与资产，独立 worker 运行真实模型；输出隔离，manifest 记录状态与哈希。
3. 可靠性：用并发进程、非零退出、缺失 executable、超时子进程树、损坏指标文件测试边界。
4. 性能工程：同步计时、tail latency、预算筛选；解释为什么 query-layer 理论减少没有转化为实际加速。
5. 展示：运行 tqinfra demo，查看 worker.log / manifest / report；有资产时演示 record 与场景 reset。

## 面试追问

- 为什么没有分布式调度？单机研究瓶颈是复现与状态追溯；目前资源锁只覆盖工作区，多个 workspace 的 GPU 竞争需要外部调度。
- 为什么哈希产物？比仅保存命令更能追踪 checkpoint/NPZ；代价是额外 I/O。
- temporal 状态怎么隔离？场景边界显式 reset，预热不写正式序列状态；流式 worker 顺序执行。
- 是不是报告页包装？控制层有真实进程隔离、失败处理和测试；性能页只是可检查的证据视图，工程代码位于 tqinfra。
